# Social Media Growth Agency Website

## Goal
Build a polished, mobile-first single-page website at `/` using `structure.md` as the authority for visible copy and numbered section order, `spec.md` for design and quality requirements, and the supplied implementation plan for component behavior. The uploaded screenshot will guide the editorial visual language only; its branding, content, imagery, and exact composition will not be copied.

## Content and page flow
Follow the numbered order confirmed by the client:

1. Hero
2. What We Do
3. Supported Platforms
4. How Our Process Works
5. 20M+ Audience Network
6. Special Promo Packages
7. Before & After — Client Proof
8. Client Reviews / Testimonials
9. Why Choose Us
10. Monetization & Brand Opportunities
11. Results & Success Stories
12. Get Started / Contact
13. FAQ
14. Footer

Preserve all client-supplied headlines, descriptions, package prices and features, FAQ wording, CTAs, numbers, and placeholders. Treat Hindi instructional sentences as implementation guidance rather than customer-facing copy. Keep `X`, `XX`, “Actual client review goes here,” “Client Name,” “Your Brand Logo,” and “Your Brand” until genuine material is supplied. Do not invent testimonials, client names, screenshots, metrics, logos, links, or case studies.

## Visual direction
- Create an original warm-white editorial design with near-black typography, light neutral bands, thin separators, restrained shadows, and mostly square or subtly rounded surfaces.
- Use a premium contemporary sans-serif hierarchy: oversized hero type, compact uppercase section labels, strong section headings, readable body copy, and prominent package pricing.
- Adapt the reference’s spacious rhythm, asymmetric compositions, precise grids, compact metadata, restrained buttons, and large visual moments.
- Use dark, purple/blue, and gold only as selective accents for CTAs, interaction states, badges, and package differentiation—not as a heavy dark or neon theme.
- Generate original social-growth imagery and analytics-inspired editorial visuals where appropriate. Use neutral placeholders for client proof areas so imagery never implies fabricated results.

## Structure and interactions
- Add a minimal sticky navigation with anchor links, a clear primary CTA, and an accessible animated mobile menu.
- Build reusable section-heading, button, service, platform, process, statistic, package, result, testimonial, FAQ, and footer patterns.
- Present services and reasons in editorial grids, platforms in a clean visual row/grid, and the six process steps as a desktop sequence that becomes a vertical mobile timeline.
- Make the 20M+ section a bold but restrained proof moment without adding unsupported statistics.
- Render four differentiated package cards for Bronze, Silver, Gold, and Diamond with clear hover, focus, and selected states; package CTAs preselect the matching contact-form option and move the visitor to the form.
- Build an accessible before/after comparison using the supplied placeholder data, with keyboard, touch, and drag support plus a static fallback.
- Build a keyboard- and swipe-friendly testimonial carousel using only the supplied placeholder review.
- Build an accessible FAQ accordion with smooth transitions.
- Build the complete contact form with labels, client-side validation, package selection, loading feedback, and a clear non-persistent success state. No database or delivery integration will be implied.
- Keep footer legal items present as supplied labels without inventing destination pages or policies.

## Responsive, motion, and quality
- Optimize the experience for phones first, then adapt grids and spacing for tablets, laptops, desktops, and wide screens.
- Prevent clipping and horizontal overflow; preserve readable type, stable image ratios, touch-sized controls, and clean stacking.
- Use restrained reveal, count-up, image-scale, carousel, menu, accordion, and hover motion; disable nonessential motion when reduced motion is requested.
- Use semantic HTML, one H1, logical heading levels, visible focus states, descriptive alt text, ARIA where needed, lazy-loaded below-the-fold imagery, and no unnecessary animation dependency.
- Add unique homepage metadata: title, description, Open Graph title/description/type, and Twitter card metadata. Replace all template metadata and placeholder content.

## Verification
- Compare every displayed section, package, FAQ, CTA, number, and placeholder against `structure.md`.
- Test navigation, mobile menu, package selection, comparison control, carousel, FAQ, and form behavior with keyboard and touch-oriented layouts.
- Check desktop and mobile screenshots for visual hierarchy, overflow, text clipping, image framing, and section order.
- Confirm the page renders cleanly, has no browser errors, and remains usable with reduced motion.
